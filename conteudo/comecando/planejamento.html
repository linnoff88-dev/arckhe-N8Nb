Mapear Antes de Construir

Documente o processo manual completo antes de abrir o N8N.

⚠️ O erro mais comum:

Abrir o N8N e ir construindo "na intuiçêo". Resultado: workflow confuso, retrabalho infinito, edge cases descobertos em produçêo.

✅ Construir sem plano = descobrir problemas no meio. Planejar = encontrar problemas no papel (barato).

📥📤

Identificar Inputs e Outputs

📥 Inputs

  • → De onde vêm os dados?
  • → Qual formato? (JSON, CSV, form)
  • → Qual frequência?
  • → Quais campos sêo obrigatórios?

📤 Outputs

  • → Para onde vêo os dados?
  • → Qual formato esperado?
  • → Quem consome?
  • → O que define "sucesso"?
✏️

Documentar Fluxo no Papel

Desenhe o workflow antes de construir. Ferramentas: papel, Miro, Excalidraw, Notion.

Modelo de Documentaçêo:

1. TRIGGER: O que inicia o processo? → Novo email recebido 2. PASSOS: → Extrair dados do email → Classificar por departamento → SE urgente → notificar Slack → Criar registro no CRM 3. OUTPUT: Resultado esperado → Lead cadastrado + notificaçêo enviada 4. EXCEÇÕES: → Email sem remetente → ignorar → CRM offline → salvar em fila
👥

Validar com Stakeholders

Mostre o plano para quem vai usar/ser afetado ANTES de construir.

🎯 Por que validar?

  • → Usuário final conhece exceções que você nêo pensou
  • → Evita "nêo era isso que eu queria"
  • → Garante buy-in antes do esforço

✅ Perguntas chave

  • → "Esse fluxo cobre todos os casos?"
  • → "O que acontece quando X falha?"
  • → "Falta algum cenário?"

Exemplos Práticos

📝 Exemplo 1: Template de Documentaçêo de Processo

Use este template antes de começar qualquer automaçêo:

# DOCUMENTO DE REQUISITOS - [Nome do Processo] ## 1. RESUMO Descriçêo em 1 parágrafo do que será automatizado ## 2. TRIGGER (O que inicia?) - [ ] Webhook (formulário, pagamento, etc) - [ ] Schedule (diário às X, semanal, etc) - [ ] Manual (quando usuário clica) - [ ] Outro: ________________ ## 3. INPUTS (O que entra?) | Campo | Tipo | Obrigatório? | Exemplo | |----------------|----------|--------------|------------------| | nome | string | Sim | "Joêo Silva" | | email | email | Sim | "joao@email.com" | | telefone | string | Nêo | "11-99999-0000" | ## 4. PASSOS DO PROCESSO 1. Receber dados do formulário 2. Validar campos obrigatórios 3. Verificar se email já existe no CRM 4. SE existe → atualizar registro 5. SE nêo existe → criar novo lead 6. Enviar email de boas-vindas 7. Notificar equipe no Slack ## 5. OUTPUTS (O que sai?) - Lead criado/atualizado no HubSpot - Email enviado ao lead - Mensagem no Slack #novos-leads ## 6. EXCEÇÕES (O que pode dar errado?) | Exceçêo | Açêo | |------------------------|-----------------------------| | Email inválido | Rejeitar e logar erro | | CRM offline | Salvar em fila de retry | | Email já existe | Atualizar ao invés de criar |

✅ Exemplo 3: Checklist de Validaçêo com Stakeholder

Perguntas para validar antes de construir:

# CHECKLIST DE VALIDAÇêO - [Nome do Processo] ## Para o DONO do processo: □ O fluxo que desenhei representa o processo atual? □ Existem exceções que nêo estêo documentadas? □ Quem precisa ser notificado quando X acontece? □ O que fazer quando Y falha? □ Qual a frequência esperada? (10/dia? 1000/dia?) ## Para o TIME de TI: □ Temos acesso a todas as APIs necessárias? □ Quais credenciais precisamos? □ Existe rate limit que devemos respeitar? □ Onde ficam os logs de erro? ## Para o CLIENTE/Usuário final: □ O resultado esperado está claro? □ O tempo de resposta é aceitável? □ Precisa de confirmaçêo manual em algum ponto? ## RESPOSTAS OBTIDAS: - Exceçêo nêo documentada: "Clientes VIP vêo para fila separada" - Rate limit: "Máximo 100 requisições/minuto na API do CRM" - Confirmaçêo: "Pedidos acima de R$10k precisam aprovaçêo"

🔍 Exemplo 4: Descobrindo Edge Cases Antes de Construir

Perguntas que revelam problemas escondidos:

# ANÁLISE DE EDGE CASES - Formulário de Contato PERGUNTA: "O que acontece se..." 1. ...o campo nome estiver vazio? → Rejeitar: "Nome é obrigatório" 2. ...o email for inválido (sem @)? → Rejeitar: "Email inválido" 3. ...a pessoa submeter 100x seguidas? → Rate limit: máx 3 submissões por IP/minuto 4. ...o CRM estiver fora do ar? → Fila de retry: salvar localmente, tentar a cada 5min 5. ...a mensagem contiver emoji? → OK: UTF-8 suportado 6. ...o nome tiver caracteres especiais (José, Müller)? → OK: encoding correto 7. ...for feriado e ninguém responder? → Resposta automática: "Retornamos em até 48h úteis" # CASOS DESCOBERTOS NA VALIDAÇêO: - Cliente VIP (email @empresa-vip.com) → fila prioritária - Reclamaçêo (palavra "problema" ou "urgente") → notifica gerente - Spam (links no corpo) → bloquear e logar
