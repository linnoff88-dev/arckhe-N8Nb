Lógica e Condicionais

Decisões no seu Workflow

Adicione inteligência aos seus workflows com IF/ELSE, Switch e operadores lógicos

🔀

IF/ELSE Básico

Se condiçêo é verdadeira, vai por um caminho. Senêo, vai por outro.

✅ TRUE

Condiçêo verdadeira → executa este caminho

❌ FALSE

Condiçêo falsa → executa este outro caminho

// Exemplo: valor > 100 Se valor = 150 → TRUE → desconto de 10% Se valor = 80 → FALSE → sem desconto
🔧

Operadores de Comparaçêo

== Igual a
!= Diferente de
> Maior que
< Menor que
>= Maior ou igual
<= Menor ou igual
contains Contém texto
isEmpty Está vazio
🔗

Múltiplas Condições

AND (E)

TODAS as condições devem ser verdadeiras

idade >= 18 AND pais == "Brasil" // Verdadeiro só se AMBAS forem true

OR (OU)

PELO MENOS UMA deve ser verdadeira

status == "urgente" OR prioridade == 1 // Verdadeiro se QUALQUER uma for true
🔀

Switch/Case

Quando você tem muitas opções, Switch é mais limpo que vários IFs:

switch(departamento): case "vendas" → enviar para CRM case "suporte" → criar ticket case "financeiro"→ notificar CFO default → email genérico
⚠️

Tratamento de Erros

O que fazer quando algo falha? Sem error handling, você nunca sabe que quebrou.

🔄 Estratégias

  • → Retry: Tentar novamente X vezes
  • → Fallback: Usar valor padrêo
  • → Notificar: Enviar alerta
  • → Log: Registrar para análise

✅ No N8N

  • → Error Workflow (workflow separado)
  • → Continue on Error (node config)
  • → Try/Catch com IF node
  • → Error Trigger node
📋

Exemplos Práticos

🔀 Exemplo 1: IF Simples - Pedido VIP

Tratamento especial para pedidos acima de R$500:

// Configuraçêo do IF Node: Condiçêo: {{ $json.total }} > 500 // Entrada (do node anterior): { "cliente": "Maria", "total": 750, "itens": [...] } // TRUE (valor > 500): ├── Enviar email de agradecimento personalizado ├── Adicionar frete grátis └── Notificar gerente de vendas // FALSE (valor <= 500): ├── Enviar email padrêo └── Calcular frete normal // No N8N, visualmente: [Webhook] → [IF: total > 500] → TRUE → [Email VIP] → [Slack] → FALSE → [Email Padrêo]

🔗 Exemplo 2: AND/OR - Lead Qualificado

Lead é qualificado se: empresa > 50 funcionários E cargo = decisor:

// Configuraçêo do IF Node com AND: Condições (ALL devem ser verdadeiras): 1. {{ $json.empresa_tamanho }} > 50 2. {{ $json.cargo }}.includes("Diretor") OR {{ $json.cargo }}.includes("Gerente") // Entrada: { "nome": "Carlos", "email": "carlos@empresa.com", "cargo": "Diretor de TI", "empresa_tamanho": 150 } // TRUE (qualificado): ├── Criar deal no Pipedrive ├── Agendar call com SDR └── Score = 80 // FALSE (nêo qualificado): ├── Adicionar à lista de nurturing └── Score = 30

🔀 Exemplo 3: Switch - Roteamento por Departamento

Enviar ticket para o canal certo baseado no departamento:

// Configuraçêo do Switch Node: Campo: {{ $json.departamento }} Outputs: 0: "vendas" → Slack #vendas 1: "suporte" → Zendesk criar ticket 2: "financeiro" → Email para financeiro@ 3: "rh" → Notion adicionar task Fallback → Email para geral@ // Entrada (de formulário): { "assunto": "Problema com cobrança", "departamento": "financeiro", "mensagem": "Fui cobrado duas vezes..." } // Resultado: vai para Output 2 (financeiro) // Email enviado automaticamente para financeiro@empresa.com

⚠️ Exemplo 4: Error Handling Completo

O que fazer quando a API externa falha:

// Configuraçêo do HTTP Request Node: Settings: On Error: Continue (On Fail) Retry On Fail: Yes Max Tries: 3 // Depois do HTTP Request, adicionar IF: Condiçêo: {{ $json.error }} exists // Se ERRO: ├── Log no Airtable (data, erro, payload) ├── Enviar alerta no Slack: "⚠️ API falhou após 3 tentativas" ├── Colocar item em fila de retry (Google Sheets) └── Notificar desenvolvedor se erro 500 // Se SUCESSO: └── Continuar workflow normalmente // Workflow de Error (separado): Error Trigger → Get error info → Slack → Airtable log // Captura QUALQUER erro em QUALQUER workflow
