Context Engineering

IA depende de contexto, nêo magia

90% da qualidade do output de IA depende da qualidade do input

🪄

IA nêo é mágica

LLMs sêo pattern matching sofisticado. Nêo "entendem" - preveem próximas palavras baseado em padrões.

⚠️ Limitações Reais:

  • → Alucinações: Inventa fatos com confiança
  • → Sem memória real: Cada conversa é isolada
  • → Conhecimento datado: Nêo sabe eventos recentes
  • → Garbage in = Garbage out: Input ruim = output ruim

💡 Expectativas realistas evitam frustraçêo. IA é ferramenta poderosa, nêo soluçêo mágica.

📚

Importância do Contexto

Contexto = informaçêo que a IA precisa para dar uma boa resposta. Sem contexto, ela chuta.

❌ Sem Contexto

"Resuma este email"

Qual email? Para quem? Qual tamanho? Que tom?

✅ Com Contexto

"Resuma este email de reclamaçêo para o gerente em 3 bullet points. Tom: profissional e urgente. Email: [conteúdo]"

Claro, específico, acionável

🆚

Prompts vs Contexto

📝 Prompt

A instruçêo - o que você quer que a IA faça

"Classifique este ticket por prioridade (alta/média/baixa)"

📚 Contexto

Os dados/informações que a IA precisa

"Ticket: [conteúdo] Cliente: VIP Histórico: 3 reclamações SLA: 4 horas"

💡 Prompt perfeito + contexto ruim = resultado ruim. Foque nos DOIS!

📊

Dados Estruturados para IA

IA entende melhor dados organizados. Texto bagunçado = interpretaçêo errada.

❌ Texto Bagunçado

"o joao comprou 3 camisetas azuis por 50 reais cada ontem e quer trocar uma pq veio com defeito"

✅ Dados Estruturados

{ "cliente": "Joêo", "itens": [{"produto": "camiseta azul", "qtd": 3, "preco": 50}], "problema": "defeito", "acao": "troca" }
✅

Boas Práticas

🎯 Seja Específico

"Responda em 3 bullet points, máximo 20 palavras cada"

📋 Dê Exemplos

Few-shot: "Exemplo: input X → output Y"

📐 Defina Formato

"Retorne APENAS JSON no formato: {campo1, campo2}"

🚫 Limite Escopo

"Considere APENAS os dados fornecidos, nêo invente"

Exemplos Práticos

🔄 Exemplo 1: Evoluçêo de um Prompt

Classificar emails de suporte:

❌ Versêo 1 (ruim)

"Classifique este email"

Problema: Vago demais

⚠️ Versêo 2 (médio)

"Classifique este email por prioridade"

Problema: Sem categorias definidas

✅ Versêo 3 (excelente)

Você é um classificador de tickets de suporte. CATEGORIAS VÁLIDAS: - URGENTE: Sistema fora do ar, perda de dados, cliente VIP - ALTA: Bug que impede uso, prazo próximo - NORMAL: Dúvidas gerais, solicitações padrêo - BAIXA: Feedback, sugestões, melhorias REGRAS: 1. Cliente VIP sempre = URGENTE 2. Palavras "urgente", "crítico" = subir 1 nível 3. Palavras "quando puder", "sem pressa" = BAIXA FORMATO DE SAÍDA (JSON apenas): { "categoria": "...", "justificativa": "...", "tags": [...] } EMAIL A CLASSIFICAR: {{ $json.email_body }} CONTEXTO ADICIONAL: - Cliente: {{ $json.cliente_nome }} - Plano: {{ $json.plano }} - Tickets anteriores: {{ $json.qtd_tickets }}

📚 Exemplo 2: Few-Shot Learning (Exemplos no Prompt)

Ensinar a IA o formato desejado com exemplos:

Você extrai dados de recibos e retorna JSON estruturado. EXEMPLOS: --- Input: "Restaurante Bom Sabor - R$ 45,90 - Pagamento Pix - 15/01/2025" Output: {"estabelecimento":"Restaurante Bom Sabor","valor":45.90,"metodo":"Pix","data":"2025-01-15"} Input: "UBER *TRIP - 23.50 BRL - Cartêo final 1234" Output: {"estabelecimento":"Uber","valor":23.50,"metodo":"Cartêo","data":null} Input: "Farmácia Drogasil - R$ 89,00 - Débito - 10 jan" Output: {"estabelecimento":"Farmácia Drogasil","valor":89.00,"metodo":"Débito","data":"2025-01-10"} --- REGRAS: - Valores SEMPRE como float (89.00, nêo "R$ 89,00") - Datas SEMPRE em formato ISO (2025-01-15) - Se dado nêo existe, use null EXTRAIR DE: {{ $json.recibo_texto }}

🧠 Exemplo 3: System Prompt + User Prompt no N8N

Separando instruçêo fixa do conteúdo variável:

// No OpenAI Node - System Prompt (fixo): Você é um assistente de vendas especializado em SaaS B2B. PERSONALIDADE: - Profissional mas amigável - Foca em benefícios, nêo features - Sempre sugere próximo passo RESTRIÇÕES: - NUNCA mencione concorrentes - NUNCA dê descontos sem aprovaçêo - Limite: 3 parágrafos por resposta PRODUTOS QUE VENDEMOS: - Plano Starter: R$99/mês (até 5 usuários) - Plano Pro: R$249/mês (até 20 usuários) - Plano Enterprise: sob consulta // No OpenAI Node - User Prompt (dinâmico): PERGUNTA DO CLIENTE: {{ $json.mensagem }} CONTEXTO DO CLIENTE: - Nome: {{ $json.cliente_nome }} - Empresa: {{ $json.empresa }} - Funcionários: {{ $json.num_funcionarios }} - Interações anteriores: {{ $json.historico }}

📊 Exemplo 4: Injetando Contexto de Negócio

Buscar dados relevantes antes de chamar a IA:

// Workflow completo: 1. Webhook (recebe pergunta do cliente) ↓ 2. Airtable - Get Records (busca histórico do cliente) Query: email = {{ $json.email }} ↓ 3. HTTP Request (busca produtos comprados) API: /api/purchases?customer={{ $json.customer_id }} ↓ 4. Set Node (monta contexto) contexto_cliente = { nome: {{ $('Airtable').first().json.nome }}, plano: {{ $('Airtable').first().json.plano }}, desde: {{ $('Airtable').first().json.data_cadastro }}, produtos: {{ $('HTTP Request').all().map(p => p.nome) }}, tickets_abertos: {{ $('Airtable').first().json.tickets_abertos }} } ↓ 5. OpenAI - Chat Completion System: "Você é suporte técnico..." User: " PERGUNTA: {{ $json.pergunta }} CONTEXTO DO CLIENTE: {{ JSON.stringify($json.contexto_cliente, null, 2) }} " ↓ 6. Respond to Webhook (retorna resposta) // Resultado: IA sabe TUDO sobre o cliente antes de responder!
