Falhar Rápido

Teste cedo, descubra problemas cedo. Nêo espere workflow "perfeito" para testar.

❌ Abordagem Ruim

Construir workflow inteiro → testar no final → descobrir que a base está errada

✅ Abordagem Boa

Construir 1 node → testar → funciona? → próximo node → testar → repetir

💡 Erro no início é fácil de corrigir. Erro no final é caro e frustrante.

🧪

Testar Limites

Produçêo sempre traz casos que teste básico nêo pega. Antecipe!

🔍 O que testar?

  • → Dados vazios ou nulos
  • → Caracteres especiais (ç, é, emoji)
  • → Volumes grandes (10.000 items)
  • → Timeouts e lentidêo
  • → APIs fora do ar

⚠️ Edge Cases Comuns

  • → Email sem assunto
  • → Nome com apenas 1 palavra
  • → Preço negativo ou zero
  • → Data em formato errado
  • → Campo obrigatório faltando
📝

Usar Logs Efetivamente

Logs sêo sua câmera de segurança. Sem logs, debug é adivinhaçêo.

No N8N:

  • ✅ Execution Log: Histórico de todas as execuções
  • ✅ Node Output: Dados de saída de cada node
  • ✅ Error Messages: Detalhes quando falha
  • ✅ Pin Data: Fixar dados para debug
🔍

Debug Passo a Passo

Executar node por node, verificando output de cada um:

1. Execute só o primeiro node

Verifique se os dados estêo corretos

2. Use "Pin Data"

Fixe os dados para nêo precisar re-executar

3. Execute o próximo node

Compare: esperado vs resultado real

4. Repita até encontrar o problema

O erro está entre o último que funcionou e o primeiro que falhou

Exemplos Práticos

🔍 Exemplo 1: Debug Passo a Passo

Workflow com erro: dados nêo chegam ao CRM. Como debugar:

# PROBLEMA: Lead nêo está sendo criado no HubSpot # WORKFLOW: Webhook → Set Node → HTTP Request (HubSpot) → Slack # PASSO 1: Executar só o Webhook Clique no Webhook → "Execute Node" Output: { "nome": "Joêo", "email": "joao@email.com" } ✅ Dados chegando corretamente # PASSO 2: Pin Data e executar Set Node Clique "Pin Data" no Webhook (fixa os dados) Execute Set Node Output: { "properties": { "firstname": "Joêo", "email": "joao@email.com" } } ✅ Transformaçêo correta # PASSO 3: Executar HTTP Request Execute HTTP Request Output: { "error": "401 Unauthorized" } ❌ ERRO ENCONTRADO! # DIAGNÓSTICO: - Status 401 = problema de autenticaçêo - Verificar: API Key expirada? Token inválido? # SOLUÇêO: 1. Ir em Credentials 2. Editar credencial do HubSpot 3. Gerar novo token na API do HubSpot 4. Atualizar no N8N 5. Testar novamente → ✅ 201 Created

Checklist de testes antes de ir para produçêo:

# CHECKLIST DE TESTES - Formulário de Lead ## DADOS VÁLIDOS (happy path) □ Teste 1: Nome e email válidos → Lead criado ✅ □ Teste 2: Todos os campos preenchidos → Lead completo ✅ ## DADOS INVÁLIDOS (sad path) □ Teste 3: Email sem @ → Erro "Email inválido" ✅ □ Teste 4: Nome vazio → Erro "Nome obrigatório" ✅ □ Teste 5: Nome com números → Aceitar (Joêo123 é válido) ✅ ## EDGE CASES □ Teste 6: Nome com acento (José) → ✅ Aceita UTF-8 □ Teste 7: Email já existente → ✅ Atualiza ao invés de criar □ Teste 8: Nome muito longo (500 chars) → ⚠️ FALHOU! Truncar para 100 □ Teste 9: Emoji no nome (Joêo 🚀) → ⚠️ FALHOU! Sanitizar ## VOLUME/STRESS □ Teste 10: 100 leads simultâneos → ✅ Processou todos □ Teste 11: Arquivo CSV com 10.000 linhas → ⚠️ Timeout 60s → Soluçêo: Split In Batches de 100 em 100 ## FALHAS EXTERNAS □ Teste 12: API HubSpot offline → ✅ Retry 3x + alerta Slack □ Teste 13: Rate limit atingido → ✅ Delay automático 1s entre calls # RESULTADO: 11/13 passaram. 2 ajustes necessários.

📊 Exemplo 3: Configurando Logs e Alertas

Monitoramento para saber quando algo quebra:

# ESTRUTURA DE LOGS E ALERTAS ## 1. LOG DE EXECUÇÕES (Airtable/Notion) Campos: - workflow_id - execution_id - status (success/error) - timestamp - input_data (resumido) - error_message (se houver) ## 2. WORKFLOW DE ERROR (separado) Trigger: Error Trigger (captura erros de qualquer workflow) Nodes: Error Trigger ↓ Set Node (formatar dados do erro) { "workflow": {{ $execution.workflow.name }}, "erro": {{ $execution.error.message }}, "node": {{ $execution.error.node }}, "timestamp": {{ $now }} } ↓ Airtable (log do erro) ↓ Slack (alerta imediato) Mensagem: "🚨 Erro no workflow {{ workflow }}: Node: {{ node }} Erro: {{ erro }}" ↓ Email (se crítico) Para: dev@empresa.com Assunto: [CRÍTICO] Workflow falhou ## 3. DASHBOARD DE MONITORAMENTO - Google Sheets ou Metabase - Gráficos: execuções/dia, taxa de erro, tempo médio - Alerta se taxa de erro > 5%
