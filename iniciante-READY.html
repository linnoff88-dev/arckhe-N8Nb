1. Schedule Trigger

Automações programadas em horários fixos

Trigger

  • O que é: Execute workflows a cada X minutos, horas, dias ou use CRON para agendamentos complexos.

    Por que aprender: Automatize tarefas repetitivas sem intervençêo manual (relatórios, backups, sincronizações).

    Conceitos chave: Intervalos fixos, expressões CRON, timezone, polling schedule.

  • O que é: Definir o fuso horário correto para garantir execuções no horário local desejado.

    Por que aprender: Evitar execuções em horários errados, especialmente em equipes globais ou servidores em outras regiões.

    Conceitos chave: UTC, GMT, timezone local, horário de verêo.

  • O que é: Exemplos reais de automações com Schedule Trigger.

    Por que aprender: Inspirar suas próprias automações vendo aplicações práticas.

    Conceitos chave: Relatórios diários, backups automáticos, newsletters semanais, monitoramento contínuo.

2. Event Trigger

Reaja a eventos em tempo real

Trigger

  • O que é: Event reage a ALGO que acontece (novo email, mensagem); Schedule executa em HORÁRIO fixo.

    Por que aprender: Entender quando usar cada tipo de trigger é fundamental para automações eficientes.

    Conceitos chave: Event-driven vs time-based, reatividade, triggers condicionais.

  • O que é: Polling verifica periodicamente (1 min); Webhook recebe notificaçêo instantânea.

    Por que aprender: Polling consome execuções; webhook é mais rápido e eficiente.

    Conceitos chave: Intervalo de polling, execuções, latência, push vs pull.

  • O que é: Gmail, Slack, Google Sheets, Trello e centenas de apps suportados.

    Por que aprender: Conectar com apps que você já usa diariamente para criar automações poderosas.

    Conceitos chave: OAuth, credenciais, filtros de eventos, conditions.

3. Webhook

Receba dados via HTTP POST/GET

API

  • O que é: Uma URL única que recebe dados de sistemas externos via requisições HTTP.

    Por que aprender: Integrar N8N com qualquer ferramenta que suporte webhooks, sem polling.

    Conceitos chave: URL endpoint, métodos HTTP (GET, POST), payload JSON, headers.

  • O que é: Test URL muda a cada ativaçêo do workflow; Production URL é fixa e permanente.

    Por que aprender: Usar Production URL para integrações reais, Test URL apenas para desenvolvimento.

    Conceitos chave: Workflow ativo vs inativo, URL persistente, ambiente de teste vs produçêo.

  • O que é: Enviar resposta de volta para quem chamou o webhook (status 200, dados JSON, etc).

    Por que aprender: Criar APIs customizadas ou confirmar recebimento de dados.

    Conceitos chave: Status codes (200, 400, 500), response body, headers customizados.

4. Split Out

Divida arrays em items individuais

Data

  • O que é: Transformar 1 item com array de 10 elementos em 10 items separados.

    Por que aprender: Processar cada elemento individualmente (enviar email para cada pessoa, criar registro por item).

    Conceitos chave: Field to split out, array destructuring, item count.

  • O que é: Sempre que API retornar lista e você quiser processar cada elemento individualmente.

    Por que aprender: Evitar loops manuais, aproveitar processamento paralelo do N8N.

    Conceitos chave: Batch processing, item-level operations, data normalization.

  • O que é: Split Out processa todos items em paralelo; Loop processa um por vez sequencialmente.

    Por que aprender: Escolher a ferramenta certa: paralelo (Split) vs sequencial (Loop).

    Conceitos chave: Parallel execution, sequential processing, performance trade-offs.

5. Aggregate

Agrupe múltiplos items em um só

Data

  • O que é: Oposto do Split Out - combina 100 items em 1 item com array de 100 elementos.

    Por que aprender: Enviar dados em lote para APIs, criar relatórios consolidados, reduzir número de items.

    Conceitos chave: Array aggregation, batch operations, data consolidation.

  • O que é: All junta todos em 1; By Field agrupa por categoria (vendas por regiêo, usuários por status).

    Por que aprender: Criar relatórios agrupados, segmentar dados por critérios específicos.

    Conceitos chave: Grouping, aggregation strategies, field-based partitioning.

  • O que é: Bulk insert em banco de dados, enviar 1000 registros de uma vez, gerar CSV completo.

    Por que aprender: Otimizar chamadas de API, reduzir custos, melhorar performance.

    Conceitos chave: Batch API calls, bulk operations, performance optimization.

6. Edit Fields (Set)

Crie ou modifique campos de dados

Data

  • O que é: Adicionar novos campos, renomear existentes, calcular valores, formatar dados.

    Por que aprender: Preparar dados para próximos nodes, transformar estrutura de dados, limpar informações.

    Conceitos chave: Field mapping, data transformation, value assignment.

  • O que é: Usar valores fixos ("aprovado") ou expressões dinâmicas ({{$json.nome.toUpperCase()}}).

    Por que aprender: Criar campos calculados, concatenar strings, formatar datas, aplicar lógica.

    Conceitos chave: Expression editor, $json variable, string manipulation, date formatting.

  • O que é: Keep Only mantém APENAS campos criados; Include Other preserva campos originais também.

    Por que aprender: Limpar dados desnecessários ou enriquecer dados existentes.

    Conceitos chave: Field filtering, data pruning, schema transformation.

7. IF

Lógica condicional (se/entêo)

Logic

  • O que é: Direcionar items que atendem condiçêo para True, os demais para False.

    Por que aprender: Criar fluxos diferentes baseados em critérios (valor > 100, status == "aprovado", etc).

    Conceitos chave: Boolean logic, conditional routing, branching workflows.

  • O que é: String (contains, equals), Number (maior, menor, igual), Boolean, Date comparisons.

    Por que aprender: Validar dados, filtrar registros, aplicar regras de negócio.

    Conceitos chave: Operators (==, !=, >, <, contains), data type comparisons, regex matching.

  • O que é: Combinar condições - AND (todas devem ser verdade), OR (pelo menos uma verdadeira).

    Por que aprender: Criar filtros complexos (status == "ativo" AND valor > 1000).

    Conceitos chave: Logical AND, logical OR, condition groups, complex filters.

8. Switch

Roteamento com múltiplas saídas

Logic

  • O que é: IF tem 2 saídas (True/False); Switch tem N saídas (0, 1, 2, 3...).

    Por que aprender: Rotear para caminhos diferentes baseado em categoria, status, prioridade.

    Conceitos chave: Multi-way branching, routing rules, fallback output.

  • O que é: Rules (condições complexas) ou Expression (retorna número da saída 0-3).

    Por que aprender: Rules para lógica visual; Expression para cálculos dinâmicos.

    Conceitos chave: Rule-based routing, expression evaluation, dynamic output selection.

  • O que é: Saída padrêo quando item nêo atende nenhuma regra.

    Por que aprender: Garantir que todos items sejam processados, tratar casos nêo previstos.

    Conceitos chave: Default routing, error handling, catch-all logic.

9. Merge

Combine dados de múltiplas fontes

Flow

  • O que é: Append (juntar tudo), Combine (mesclar por posiçêo), Match (join por campo-chave).

    Por que aprender: Enriquecer dados, unir resultados de APIs diferentes, criar datasets completos.

    Conceitos chave: Append mode, combine by position, key-based matching, left/inner join.

  • O que é: Conectar 2+ nodes anteriores ao Merge para combinar seus dados.

    Por que aprender: Processar dados em paralelo e depois unir resultados.

    Conceitos chave: Multiple inputs, parallel processing, data synchronization.

  • O que é: Combinar registros que possuem mesmo valor em campo-chave (como SQL JOIN).

    Por que aprender: Enriquecer dados de clientes com informações de vendas, unir tabelas relacionadas.

    Conceitos chave: Key fields, inner join, left join, data enrichment.

10. Loop Over Items

Processe items sequencialmente em loop

Advanced

  • O que é: Loop processa 1 item por vez em sequência; Split Out processa todos em paralelo.

    Por que aprender: Use Loop quando ordem importa ou quando precisa de rate limiting.

    Conceitos chave: Sequential processing, iteration, rate limiting, order preservation.

  • O que é: Processar X items por vez (ex: 100 de cada vez) ao invés de 1 por 1.

    Por que aprender: Otimizar performance com batch processing, respeitar limites de API.

    Conceitos chave: Batch size, pagination, API limits, performance optimization.

  • O que é: Rate limiting (max 1 request/segundo), processamento ordenado, wait entre items.

    Por que aprender: Evitar bloqueios de API, processar grandes volumes gradualmente.

    Conceitos chave: Throttling, sequential execution, controlled processing.

11. Wait

Pause workflow temporariamente

Flow

  • O que é: Duraçêo fixa (5 segundos), Até data específica, Aguardar webhook/evento.

    Por que aprender: Rate limiting, aguardar processamento externo, workflows multi-etapa.

    Conceitos chave: Time-based wait, event-based wait, resumable workflows.

  • O que é: Pausar workflow até receber resposta via webhook (aprovaçêo, confirmaçêo).

    Por que aprender: Criar workflows com interaçêo humana, processos de aprovaçêo.

    Conceitos chave: Human-in-the-loop, approval workflows, webhook resume.

  • O que é: Máximo de espera (timeout após 7 dias), limites de execuções simultâneas aguardando.

    Por que aprender: Planejar workflows de longa duraçêo, entender custos e limites.

    Conceitos chave: Execution limits, timeout handling, long-running workflows.

12. HTTP Request

Conecte com qualquer API REST

API

  • O que é: GET (buscar), POST (criar), PUT/PATCH (atualizar), DELETE (remover).

    Por que aprender: Integrar com qualquer API REST do mercado.

    Conceitos chave: REST methods, CRUD operations, idempotency.

  • O que é: Bearer Token, API Key, Basic Auth, OAuth2.

    Por que aprender: Acessar APIs protegidas com segurança.

    Conceitos chave: Authentication methods, API keys, OAuth flows, headers.

  • O que é: Headers (Content-Type, Authorization), Body (JSON, Form, Raw).

    Por que aprender: Configurar requisições corretamente, enviar dados estruturados.

    Conceitos chave: HTTP headers, request body, JSON payload, content types.

13. Code

Execute JavaScript/Python custom

Advanced

  • O que é: Executar código customizado quando nodes visuais nêo sêo suficientes.

    Por que aprender: Fazer transformações complexas, cálculos avançados, lógica personalizada.

    Conceitos chave: JavaScript runtime, Python support, custom logic.

  • O que é: Run Once para todos items; Run for Each processa item por item.

    Por que aprender: Escolher modo correto conforme necessidade (agregaçêo vs transformaçêo individual).

    Conceitos chave: Execution modes, $input.all() vs $input.item, item iteration.

  • O que é: Bibliotecas incluídas (luxon, axios), sandbox seguro, timeout de execuçêo.

    Por que aprender: Entender capacidades e restrições do ambiente de execuçêo.

    Conceitos chave: Built-in libraries, sandbox environment, execution timeout.

14. Execute Workflow

Chame outros workflows

Flow

  • O que é: Dividir workflows grandes em módulos menores reutilizáveis.

    Por que aprender: Manter código organizado, reutilizar lógica comum, facilitar manutençêo.

    Conceitos chave: Sub-workflows, reusability, modular design.

  • O que é: Enviar dados para workflow filho, receber resultado de volta.

    Por que aprender: Criar workflows parametrizáveis, implementar funções reutilizáveis.

    Conceitos chave: Input data, return values, workflow parameters.

  • O que é: Aguardar workflow terminar (síncrono) ou disparar e continuar (assíncrono).

    Por que aprender: Controlar execuçêo, processar resultados ou disparar fire-and-forget.

    Conceitos chave: Synchronous execution, asynchronous calls, workflow orchestration.

15. Error Trigger

Capture e trate erros de workflows

Advanced

  • O que é: Workflow separado que é executado quando outro workflow falha.

    Por que aprender: Log de erros, notificações, retry automático, monitoramento centralizado.

    Conceitos chave: Error handling, workflow monitoring, failure recovery.

  • O que é: Recebe informações sobre erro (mensagem, stack trace, workflow, node).

    Por que aprender: Debug eficiente, criar alertas contextualizados, análise de falhas.

    Conceitos chave: Error metadata, stack traces, execution context.

  • O que é: Enviar email quando workflow falha, salvar log em banco, notificar Slack.

    Por que aprender: Monitoramento proativo, SLA compliance, operaçêo profissional.

    Conceitos chave: Error notifications, logging, incident management.

16. Respond to Webhook

Envie resposta de volta ao webhook

API

  • O que é: Retornar status HTTP correto (200 sucesso, 400 erro, 500 falha).

    Por que aprender: Comunicar resultado da operaçêo para sistema chamador.

    Conceitos chave: HTTP status codes, success/error responses, API standards.

  • O que é: Enviar dados JSON, configurar headers customizados (Content-Type, CORS).

    Por que aprender: Criar APIs completas com N8N, integrações bidirecionais.

    Conceitos chave: Response payload, custom headers, CORS configuration.

  • O que é: Responder antes de processar (202 Accepted) ou após completar workflow.

    Por que aprender: Evitar timeouts, implementar processamento assíncrono.

    Conceitos chave: Async processing, early response, timeout prevention.

17. AI Agent

Crie agentes inteligentes com ferramentas

AI

  • O que é: Chat Model apenas conversa; Agent pode usar TOOLS (buscar dados, executar ações).

    Por que aprender: Criar assistentes que interagem com sistemas reais, nêo só conversam.

    Conceitos chave: Tool calling, function calling, agentic behavior.

  • O que é: Conectar sub-workflows que AI pode chamar (buscar cliente, criar ticket, enviar email).

    Por que aprender: Dar superpoderes para AI interagir com seus sistemas.

    Conceitos chave: Tool definition, workflow tools, AI function calling.

  • O que é: Instruções de comportamento, escolha de modelo (GPT-4, Claude), temperatura, tokens.

    Por que aprender: Controlar personalidade e capacidades do agent.

    Conceitos chave: System prompts, model selection, temperature, max tokens.
